# 레퍼런스 분석 (2026-09-29)

> 캡처에 실제 학생·학부모 개인정보가 있으므로 캡처 원본은 저장소에 올리지 않는다. 이 문서에는 화면 구조만 적는다.

## 에듀OK (현재 학원이 쓰는 관리 프로그램) — 재학생 화면

### 레이아웃
- 상단 바: 로고 · 원격지원 · 매뉴얼 · 로그아웃 · 오류접수
- 메인 메뉴: 학생관리 / 상담관리 / 수납관리 / SMS·푸시 / 학원관리
- 학생관리 하위 메뉴: 재학생 · 출결내역 · 휴학생 · 퇴원생 · 입학희망생 · 전체학생 · 학생현황

### 재학생(=출결 메인) 화면
- 날짜 이동 (◀ 2026년 09월 29일 (화) ▶), 정렬(이름), 생일(당일), 보기(학생별), 화면설정
- 반 필터 칩 + 인원: 전체반(10), OB-초고, OB-초저, OB-초중, 중등(브릿지), 고등-코어, 고등-마스터, 고등-포커스, 초고, 초중 / 담임 필터
- 상태 필터: 전체 · 미등원 · 등원 · 하원 · 결석 (각 인원수), 요일, 수납일, 수납상태, 검색, 학생등록
- 학생 카드 그리드: 이름(학교+학년), 등원 시각, 하원 시각, [출결] 버튼, [납부/미납] 배지, 선택 체크박스
  - 카드 배경색으로 등원/하원/결석 구분, 아이콘으로 SMS·push·Talk 발송 여부 표시
- 하단 일괄 작업: 선택 학생 → 출결등록 · 정보수정 · SMS/푸시 보내기 (대상: 학생 / 보호자1 / 보호자2)
- 규모: 재원생 약 67명, 반 약 10개

### 학생 상세 팝업 → 새 앱 데이터 모델 참고
- 기본: 학생번호, 학생전화, 이름(학교+학년), 생년월일(양/음), 반, 입학일, **인증번호(=학생 전화 뒷 4자리, 출결용)**, 수납일
- 보호자(복수): 이름, 관계, 휴대전화, 앱 설치 여부, 출결알림 사용, 자동알림 사용
- 기타: 메모, **등원요일(예: 월,수,금)**, 추가정보(정의 필드 여러 개)

### 새 앱에 주는 시사점
- 요구사항 문서의 "선생님 기본 화면"은 이 재학생 화면 기반 + 오른쪽에 숙제/학부모 채팅 패널을 붙인 형태
- 학생 1명에 보호자 여러 명 → 학생–학부모 N:M 관계 필요
- 등원요일로 "오늘 올 학생"과 "미등원"을 계산
- 수납일/납부 상태가 카드에 바로 보여야 함 (원장만)

## 에듀OK 학생 리스트 (전체학생, 80건) — 데이터 구조 관찰
캡처에 실명·전화번호가 있으므로 여기에는 구조와 패턴만 기록한다.

- 컬럼: 반 · 이름 · 휴대전화 · 보호자 · 휴대전화1 · 휴대전화2 · 입학일 · 휴/퇴원일 · 메모
- 상태: 이름 앞에 (재)/(휴)/(퇴) 표시. 80명 중 재원 약 67명, 나머지는 휴원·퇴원 (퇴원생도 기록 유지)
- 목록에서 반은 1개만 표시됨. 우리 앱은 N:M으로 가되 "대표 반" 개념이 있으면 이관이 쉬움
- **학교·학년이 이름 안에 자유 텍스트로 들어 있음** ("홍길동(고림중3)", "홍길동 초6", "홍길동.고진중3", 학교 없이 이름만 있는 경우도 있음) → 새 앱은 학교/학년을 별도 필드로 두고, 이관할 때 파싱이 필요함
- **보호자는 1명(이름 = "OO맘", "엄마", "OO(부)" 등 자유 텍스트) + 전화 2개** 구조. 관계 필드가 따로 없음
- **형제자매가 보호자 전화를 공유**함 (메모에 "OO 동생", "OO 누나") → 학부모 계정 1개에 자녀 여러 명 연결 필요
- **학생 휴대전화가 없는 경우**, 그리고 **형제가 같은 학생 번호를 쓰는 경우**가 있음 → 전화번호를 학생 로그인 ID로 쓰면 유일하지 않음. 별도 로그인 ID나 예외 처리가 필요함
- 전화 뒷 4자리(출결번호)가 **학생끼리 겹치는 경우가 있음** → 출결은 선생님 입력으로 결정했으므로 치명적이지 않지만, 번호를 고유 키로 쓰면 안 됨
- **메모에 개인별 수업 시간표가 들어 있음** ("월수 2h", "화목 3시 시작 2시간", "월수목 80분" 등) → 수업 시간은 반이 아니라 **학생마다 다름**. 새 앱에는 학생별 요일·시작시간·수업시간 필드가 필요함 (오늘 올 학생 / 미등원 계산에 사용)
- 메모에 "OB 멤버: -2만원" → **학생별 수강료 할인**. OB = 기존생 그룹으로 추정(원장님 확인 필요). 반 이름에도 OB-초고/OB-초중/OB-초저가 있음
- 입학일이 미래인 재원생이 있음 (예정 학생) → 시작일 개념이 필요함
- 반 목록: 초고, 초중, 중등(브릿지), 고등-코어, 고등-마스터, 고등-포커스, OB-초고, OB-초중, OB-초저
- 운영 데이터에 "테스트" 학생이 섞여 있음
- 베타 코드에 하드코딩된 학생 3명은 실제 재원생이다 (원장님 저장소에 실제 번호가 들어 있음)
