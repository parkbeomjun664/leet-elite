# 디자인 시스템 (시각 + 모션)

리트영어학원 전용 디자인 기준. 모든 화면은 이 문서의 토큰과 `src/components/ui/` 부품만 쓴다.
미리보기: `/design-system` (직접 눌러 볼 수 있음). 결정 기록은 `docs/decisions.md` 10/5 "디자인 시스템".

## 0. 방향: 차분한 신뢰감 + 빨강 한 방울 + 부드러운 반응

- 화면 대부분은 흰색과 중립 회색. 빨강(brand)은 **그 화면에서 가장 중요한 행동 하나**(주요 버튼)와 로고에만
- 분홍(brand-tint)은 결석·경고에만. 선택 표시는 진한 테두리(ink)
- 누르면 바로 반응한다. 저장을 기다리지 않고 화면을 먼저 바꾸고(낙관적 업데이트), 실패하면 되돌리고 알린다
- 참고: 채널톡(목록 + 상세), Linear(절제된 색), 토스(숫자 위계·여백·부드러운 반응)
- 눈에 띄는 것은 두 가지뿐: 빨강 주요 버튼, 누름 반응. 나머지는 조용하게. 장식(그라데이션·짙은 그림자·테두리 겹치기)은 쓰지 않는다

### 1-1. 구역 경계 (10/7 오후, 범준님)
- 원장님·선생님 화면: **흰 바탕**(레이아웃 ). 카드(테두리 + 둥근 모서리 + 흰 상자)로 구역을 감싸지 않는다
- 구역은 **여백 48px → 작은 회색 라벨(13px semibold ) → 필요한 곳만 1px 선()** 순서로 나눈다. 목록은 행 사이 선만
- 칸 모양을 남기는 곳: 누르는 단위인 선생님 홈 학생 칸·재원생 휴대폰 카드(옅은 회색  칸, 고르면 흰 바탕 + 검은 테두리)
- 오른쪽 상세(선생님 홈)는 왼쪽 1px 선으로만 나눈다. 표는 위아래 1px 선만
- 원장님 홈: 날짜 + 기준 시각 → 오늘 숫자 가로 한 줄(숫자 24 + 라벨 13, 칸 사이 세로선, 0은 회색·결석만 빨강) → 바로가기 4개 텍스트 링크 → 확인할 일 목록("보기 ›") → 보강·메시지 2단 목록
- 학생·학부모 휴대폰 화면은 이번 범위 밖(연회색 바탕 + 흰 카드 그대로)
- (같은 날 오전의 "연회색 바탕 + 흰 카드"는 템플릿 같아 이것으로 바꿈)

## 2. 글자

글꼴 Pretendard Variable 하나. 숫자(시간·인원)는 `tabular`(폭 같은 숫자).

### 크기 5단계
| 이름 | 크기 / 굵기 | 쓰는 곳 |
|---|---|---|
| 제목 `title` | 22px bold | 화면 제목(날짜), 휴대폰 맨 위 핵심 문장 |
| 소제목 `heading` | 16px semibold | 구역 제목, 학생 이름, 시트 제목 |
| 본문 `body` | 15px regular·medium | 본문, 표, 목록, 버튼, 입력칸 |
| 보조 `caption` | 13px regular | 라벨, 시각, 학교·학년, 배지, 안내 |
| 숫자 `figure` | 24px bold, tabular | 상단 통계 숫자, "확인할 일" 건수 |

- 굵기는 regular(400)·semibold(600)·bold(700) 세 가지. medium(500)은 휴대폰 본문에만, extrabold 쓰지 않음
- 줄 간격: 제목·숫자 1.3, 본문 1.5, 보조 1.45
- 하단 탭 글씨 11px는 아이콘 밑 이름표라, 상단 로고 글씨(LEET 17px)는 로고라 예외로 둔다

### 출결 키패드 (별도 크기)
학원 입구 저가 태블릿, 서서 손가락으로 누른다.
| 이름 | 휴대폰 세로 | 태블릿(md 이상) |
|---|---|---|
| 숫자 버튼 글씨 | 48px bold | 56px bold |
| 입력한 번호 칸 | 48px bold | 56px bold |
| 결과 (이름·"등원했습니다") | 40px bold | 48px bold |
| 버튼 글씨·시각 (지우기·상단 시계·처리 시각) | 24px bold | 28px bold |
| 안내 문장 (출결 번호를 누르세요·다시 입력해 주세요) | 20px semibold | 24px semibold |
| 버튼 터치 영역 | **최소 72px** | 88px |

- 그 밖의 작은 안내(번호를 잊었으면…)는 일반 단계(본문 15)를 쓴다. 번호 칸은 4개, [확인] 없음(4자리가 차면 바로 처리, 10/5). 지우기는 흰 칸, 휴대폰 세로에서는 그림만

## 3. 여백·모서리

- 여백은 4의 배수: 4 · 8 · 12 · 16 · 20 · 24 · 32 · 40 · 48
  - 카드 안쪽: 관리 16, 휴대폰 20 / 같은 묶음 카드 사이 8~12 / 구역 사이 24(관리)·28(휴대폰, 10/2 결정 유지)
- 모서리 4단계: `radius-badge` 4px · `radius-control` 6px(버튼·입력칸) · `radius-card` 8px(관리 카드·시트) · `radius-mcard` 12px(휴대폰 카드·하단 시트) · 원형(점·아바타)
- 구분은 테두리 대신 **바탕 단차·구분선·여백**으로. 테두리 안에 테두리를 넣지 않는다
- 터치 영역: 휴대폰 버튼·목록 줄 최소 44px (키패드는 72px)

## 4. 공통 부품 규칙 (`src/components/ui/`)

### 버튼 `Button`
| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 주 `primary` | brand 바탕 + 흰 글씨 | 화면(또는 시트)마다 하나: 저장, 출결 처리, 로그인, 제출하기 |
| 보조 `secondary` | 흰 바탕 + `line` 테두리 + ink 글씨 | 나머지 행동: 취소, ○○ 보기, 엑셀 내보내기 |
| 텍스트 `ghost` | 바탕 없음, 올리면 `line-soft` | 줄 안의 작은 행동, 전체 보기, 펼치기 |

- 크기: `sm` 32px(카드 안) · `md` 40px(기본) · `lg` 48px(휴대폰 주 버튼·로그인·시트 아래 버튼)
- 누름 반응: `scale(0.97)` 150ms. 비활성은 `line-soft` 바탕 + `faint` 글씨(분홍처럼 보이지 않게)
- **상태 5가지 (10/6)**: 기본 · 누름(CSS `press`) · 로딩(`state="loading"`, 빙글 표시) · 완료(`state="done"`, 체크가 튕기며 나타남) · 비활성(`disabled`). 로딩·완료 중에는 글자를 투명하게 남겨 **버튼 크기가 그대로**이고, `aria-disabled`로 다시 눌리지 않는다(회색으로 바뀌지 않음). 완료는 1초쯤 보여 준 뒤 기본으로
  - 로딩은 서버 응답을 기다려야 하는 행동에만(로그인·비밀번호 변경). 누르는 즉시 화면이 바뀌는 행동(출결·메시지)은 로딩 대신 7번 낙관적 업데이트
- 카드 안 [하원]·[출결] 같은 작은 버튼은 보조 `sm`. 흰 카드 위가 아니라 `bg` 카드 위면 흰 바탕 + `shadow-chip`

### 카드
- 관리 화면: 흰 페이지 위에서는 테두리 없이 `bg` 바탕 카드(학생 칸) 또는 구분선 목록. 오른쪽 상세 패널만 바깥 테두리 하나 허용, 그 안은 구분선만
- 휴대폰: `bg` 페이지 위 흰 카드, 모서리 12, 안쪽 20, 테두리 없음
- 누를 수 있는 카드는 누름 반응(`scale(0.98)`, 카드는 버튼보다 덜 줄어든다)

### 배지 `Badge`
- 상태색 바탕 + 진한 글씨, 모서리 4, 13px semibold, 높이 22(관리)·26(휴대폰)
- 선생님 홈 학생 칸 상태는 배지 대신 점 + 글자(10/1 결정 유지)

### 입력칸 `Input` `Select` `Textarea`
- 높이: 관리 40px, 휴대폰·로그인 48px. 흰 바탕 + `line` 테두리, 모서리 6
- 초점: 테두리 `ink/50` + 바깥 3px `line-soft` 링. 오류: 테두리 `brand` + 아래 13px brand 문장
- 시간은 `TimeSelect`(24시간제)

### 탭 (2종만)
| 종류 | 모양 | 쓰는 곳 |
|---|---|---|
| 밑줄 탭 `Tabs` | 선택: ink 글씨 semibold + 2px ink 밑줄 / 미선택: `sub` | 화면을 바꾸는 것: 상단 메뉴, 하위 메뉴, 자녀 전환, 선생님 상단 숫자 |
| 알약 `Segment` | 선택: ink 바탕 흰 글씨 / 미선택: 글씨만, 올리면 `bg` | 같은 화면 거르기: 반 거르기, 대화방 전환 |

- 상단 메뉴 선택도 빨강이 아니라 ink 밑줄 (빨강은 로고·주 버튼에만)
- 밑줄은 선택이 바뀔 때 200ms로 새 자리로 미끄러진다. 알약은 바탕색이 150ms로 바뀐다

### 빈 상태 `EmptyState`
- 가운데 정렬: `faint` 아이콘 24px → 본문 15px ink 한 문장 → (있으면) 13px `sub` 안내 → (있으면) 보조 버튼
- 바탕 없음 또는 `bg`. 점선 테두리·빨강 글씨 쓰지 않음
- 문장은 상황 + 할 수 있는 일: "아직 주고받은 메시지가 없어요" / "오늘은 수업이 없어요"

### 토스트 `Toast`
- 아래 가운데(휴대폰은 하단 탭 위), ink 바탕 + 흰 글씨 15px, 모서리 8, `shadow-float`
- 성공: 초록 체크 아이콘 + "하원 처리했어요" (버튼 이름과 같은 동사). 2.5초 뒤 사라짐
- 실패: brand 경고 아이콘 + 무엇이 안 됐는지 + 할 일. "저장하지 못했어요. 다시 눌러 주세요" 4초, 사과하지 않는다
- 동시에 하나만(새 것이 이전 것을 바꾼다). 화면 읽기 프로그램용 `role="status"`(실패는 `alert`)

### 스켈레톤 `Skeleton`
- 실제 모양과 같은 자리에 `line-soft` 블록(글씨 줄은 높이 12~16, 모서리 4)
- 1.2초 간격으로 옅어졌다 진해짐. 움직임 줄이기 설정이면 멈춘 회색
- 목록·상세 패널에만. 0.2초 안에 끝나는 로딩에는 보이지 않게 한다(깜빡임 방지)

### 시트
- 관리 화면: 오른쪽에서 나오는 시트(폭 440~480), `shadow-float`, 뒤 덮개 ink 30%
- 휴대폰: 아래에서 올라오는 하단 시트, 위 모서리 12, 손잡이 막대

## 5. 사용자별 톤

| 사용자 | 톤 | 기준 |
|---|---|---|
| 선생님 | 밀도 높게 | 한 화면에 반 전체. 카드 안쪽 12~16, 본문 15, 목록 + 오른쪽 상세(채널톡식). 숫자는 0이면 회색 |
| 원장님 | 한눈에 | 확인할 일 먼저(0이면 숨김), 숫자는 24px 오른쪽 정렬, 흰 바탕 |
| 학생 | 할 일 중심 | 맨 위에 오늘 할 숙제 + [제출하기] 하나. 나머지는 아래 목록 |
| 학부모 | 상태 한눈에 | 맨 위 한 문장 "14:38 등원했어요" + 상태색 카드. 나머지는 목록 |
| 키패드 | 초대형 | 서서 손가락으로 누르기 쉬운 큰 버튼. 누름 반응·완료 표시 말고는 움직이지 않는다 |

## 6. 모션

### 시간·곡선
| 토큰 | 값 | 쓰는 곳 |
|---|---|---|
| `--duration-fast` | 150ms | 누름 반응, 색·바탕 바뀜, 사라짐 |
| `--duration-base` | 200ms | 탭·알약 이동, 토스트 나타남, 덮개 |
| `--duration-slow` | 250ms | 시트·하단 시트 열림, 숫자 변화 |
| `--ease-out` | cubic-bezier(0.22, 1, 0.36, 1) | 나타나는 것·움직이는 것 전부 |
| `--ease-in` | cubic-bezier(0.4, 0, 1, 1) | 사라지는 것(닫힘은 열림보다 짧게, 150ms) |

### 원칙
- 움직임은 **사람이 한 행동에 답할 때만**. 화면이 열릴 때 구역마다 떠오르는 효과, 카드마다 올리면 들썩이는 효과는 쓰지 않는다
- 크기·위치(transform)와 투명도(opacity)만 움직인다. 폭·높이·여백은 움직이지 않는다(저가 기기에서 끊김)
- **움직임 줄이기 설정(prefers-reduced-motion)이면 모든 움직임을 끈다.** 색 바뀜은 남긴다
- 라이브러리 없이 CSS로. 숫자 변화만 작은 훅(`useAnimatedNumber`)

### 어디에 무엇을
| 반응 | 방법 |
|---|---|
| 누름 반응 | 버튼 `scale(0.97)`, 카드 `scale(0.98)`, 150ms. 공통 부품 안에서 처리 |
| 탭 전환 | 밑줄이 새 자리로 200ms, 알약은 바탕색 150ms |
| 오른쪽 시트 | 오른쪽에서 24px 밀려 들어오며 나타남 250ms, 닫힘 150ms (Esc·바깥·×·`useSheetClose`) |
| 하단 시트 | 아래에서 올라옴 250ms, 덮개 200ms |
| 토스트 | 아래에서 8px 올라오며 나타남 200ms |
| 숫자 변화 | 이전 숫자 → 새 숫자로 250ms 동안 세어 올라감/내려감 |
| 스켈레톤 | 1.2초 옅어졌다 진해짐 |

### 출결 키패드 예외
- 누름 반응(눌린 버튼 바탕 `line-soft` + `scale(0.96)`, 100ms)과 완료 표시만: 숫자가 칸에 들어갈 때 톡(140ms). 등원·하원은 전체 화면 완료 표시(`components/kiosk/result-overlay.tsx`): 덮개 200ms → 체크 원 스프링 400ms(0.85→1.08→1) → 체크 그리기 → 글자 0.1초 간격으로 올라옴 → 진행 막대 2.5초. 없는 번호는 번호 칸이 좌우로 흔들림(360ms)
- 시트·숫자 세기·스켈레톤 없음. 저가 태블릿에서도 끊기지 않게

## 7. 낙관적 업데이트 (누르는 즉시 반영)

대상: 출결 입력·하원 버튼(선생님), 메시지 보내기(학생 상세 미니 창). 숙제 제출·메시지 전체 화면은 만들 때(4·5단계) 같은 방식.

1. 누르면 화면을 먼저 바꾼다 (React `useOptimistic`)
2. 뒤에서 저장한다. 지금은 가짜 저장(DB 연결 전), DB를 연결하면 저장 함수만 바꾼다
3. 성공: 토스트 "하원 처리했어요"
4. 실패: 화면을 누르기 전으로 되돌리고 실패 토스트. 입력하던 글(메시지)은 지우지 않고 남긴다
5. 저장 중에도 다른 학생을 계속 누를 수 있다. 여러 저장이 동시에 진행되면 React가 모두 끝난 뒤 한 번에 확정하고, 실패한 것만 되돌린다(화면은 이미 바뀌어 있어 기다림이 보이지 않는다)

공통 훅: `useOptimisticSave` (`src/lib/`). 성공·실패·되돌림은 단위 테스트, 화면은 Playwright로 실패를 흉내 내어 확인.

## 8. 한눈에 · 부드러움 · 반응형 (10/6 보강)

10/6 범준님 요청(토스 수준 보강). 오전에 원칙만 정리했다가, 같은 날 범준님 결정으로 **전 화면에 적용**했다(브랜치 `design-toss`). 토스의 폰트·아이콘·이미지는 쓰지 않고 원칙만 참고한다(폰트 Pretendard 유지).

**적용한 곳 (10/6)**
| 원칙 | 어디에 |
|---|---|
| 하단 시트(끌어서 닫기) | `Sheet` 하나가 768 미만이면 하단 시트, 이상이면 오른쪽 패널. 학생 상세·출결 입력·학생 수정 모두 |
| 화면 전환 | `PageTransition`(React `<ViewTransition>`, Next 16.3은 설정 없이 지원). 원장님·선생님·학생·학부모 본문. 주소가 바뀔 때만, 메뉴·탭은 그대로 |
| 하단 고정 주 버튼 | `MobileStickyAction`: 학생 [제출하기](남은 숙제가 있을 때), 학부모 [결석 신청하기](보조 모양). 로그인·비밀번호 화면은 입력칸 바로 아래가 키보드가 떠도 누르기 좋아 그대로 |
| 숫자 먼저 | 학생 홈 "n개 남음", 원장님 확인할 일 |
| 표 → 카드 | 재원생 목록: 1024 미만은 카드(태블릿 2열) |
| 터치 44px | 휴대폰에서 `Button sm`·알약·날짜 이동·로고·[전체 보기]·학생 칸 이름·[하원]을 44px (768 이상은 그대로) |
| 글자 clamp | `--text-title` 22→24, `--text-figure` 24→28 |
| 학생·학부모 폭 | PC에서 가운데 480 |
| 흔들림 0 | Pretendard를 `font-display: optional`로(`src/app/pretendard.css`, `scripts/make-font-css.mjs`). 글꼴이 늦게 오면 그 화면은 기본 글꼴, 다음 방문부터 저장된 글꼴 |

- 선생님 홈 묶음 순서는 원장님 원문(오늘 등원 → 등원 전 → 수업 없음)을 유지한다. 수업 전·미등원은 위 숫자 칸을 눌러 거른다
- 측정(10/6, 빌드판·CPU 4배 느리게·캐시 없음, 내 컴퓨터): LCP 0.2~0.5초, CLS 전 화면 0 (선생님 휴대폰 0.205 → 0, 원인은 글꼴 늦게 도착)
- Lighthouse(10/6, 휴대폰·느린 4G 흉내·처음 방문): **접근성 7개 화면 모두 100**, 성능 83~95 (기준 90은 학생·키패드만 통과). 공통 원인은 CSS(25KB, 글꼴 선언 92개 포함)를 받는 동안 화면이 멈추는 시간. `experimental.inlineCss`는 오히려 82~91로 나빠져 쓰지 않는다(HTML 314KB). 다시 오는 사용자(캐시 있음)는 대부분 100에 가깝다

### 한눈에
- **한 화면 한 목적**: 핵심 정보 1개, 주요 행동 1개만 강조
  - 학생: 오늘 할 숙제 / 학부모: 오늘 등원 여부 / 선생님: 수업 전·미등원 학생 / 키패드: 번호 입력 / 원장님: 확인할 일
- **숫자 먼저**: 핵심 숫자는 `text-figure`, 설명은 13px 회색 라벨
- **문장 최소화**: 라벨은 짧게, 긴 설명은 접어 두고 필요할 때 펼치기
- **여백으로 구분**: 구분선·테두리를 줄이고 여백과 묶음으로
- **휴대폰 주 버튼은 아래 고정**(엄지 자리): `pb-[env(safe-area-inset-bottom)]` 반영, 버튼 높이 48

### 부드러움
- **화면 전환**: 페이지 이동 때 살짝 밀려오는 전환. View Transitions를 지원하는 브라우저만, 아니면 바로 바뀜. 움직임 줄이기면 끔
- **하단 시트**: 휴대폰의 상세·입력은 전체 화면 창 대신 아래에서 올라오는 시트, 손잡이·제목 줄을 아래로 96px 이상(또는 빠르게) 끌면 닫힘, 조금만 끌면 제자리
- **흔들림 0**: 이미지·로딩 자리는 크기를 미리 잡고 스켈레톤으로 채운다
- **버튼 5가지 상태**: 4번 버튼
- **빈 화면·에러 화면**: 안내 문장 + 다음 행동 버튼. 에러는 `StatusScreen`(`src/components/status-screen.tsx`): `app/error.tsx`(다시 시도·처음 화면으로), `app/not-found.tsx`, `app/global-error.tsx`

### 반응형
- 모바일 우선. 기준 폭 **375(휴대폰) · 768(태블릿·키패드) · 1280(PC)**
- 선생님·원장님: PC는 목록 + 오른쪽 상세, 태블릿 이하는 목록 → 상세 화면 전환(또는 하단 시트)
- 학생·학부모: 휴대폰 기준, PC에서는 가운데 최대 480px
- 글자 크기는 필요한 곳만 `clamp()`로 폭에 따라(제목·숫자). 본문은 15 고정
- 터치 영역 44px 이상, 가로 스크롤 생기는 화면 없게. 표는 휴대폰에서 카드형으로
- 화면을 바꾸면 세 폭 캡처로 확인하고, 핵심 행동(출결 입력, 숙제 제출)은 세 폭 화면 흐름 테스트

### 성능
- 목표: LCP 2.5초 이하, CLS 0.1 이하, 누른 뒤 반응 0.2초 이하
- 무거운 부품은 필요할 때 불러오기, 긴 목록은 보이는 만큼만
- 키패드는 저가 태블릿 기준으로 움직임이 끊기지 않는지 확인
