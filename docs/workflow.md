# 작업 방식 (범준님과 Claude가 반복해서 쓰는 규칙)

CLAUDE.md의 "작업 규칙"·"개인정보·보안"에 있는 내용은 여기에 다시 적지 않는다. 여기는 그 밖에 세션을 거치며 정한 방식이다.

## 1. 하루 진행

- 범준님은 하루 목표를 한 번에 말한다. Claude는 기능 단위로 쪼개서 하나씩 끝낸다: 만들기 → tsc·lint·테스트 → **화면 캡처로 직접 확인** → 로컬 커밋
- 기능 하나가 끝나면 짧게 보고한다: 무엇을 했나 / 어디서 보나(파일·주소) / 확인할 점 + 커밋 해시. 새 개념이 나왔으면 끝에 "오늘의 코드 포인트" 2~3개를 비유로 붙이고 `docs/code-guide.md` "날짜별 배운 것"에 적는다
- "현황"을 물으면 `docs/progress.md`의 단계 표와 `docs/requirements.md`의 요구사항 ID를 기준으로 답한다. "화면(가상 데이터)"과 "실제 동작(DB 연결)"을 나눠 말한다
- 디자인·화면 개선은 바로 고치지 않고 **찾은 문제 목록 → 범준님이 고름 → 고른 것만 적용**. 적용한 것과 보류한 것은 `docs/decisions.md`에 적는다
- 큰 디자인 변경은 앱 코드와 분리된 시안(디자인 캔버스)으로 먼저 보여 준다. frontend-design 스킬은 정해 둔 토큰·규칙 안에서 배치·위계를 다듬을 때만 쓴다

## 2. 작업일지 (작업 내역)

- 범준님이 작업일지 시트(날짜 · 시작 · 끝 · 총 시간 · 작업내역)에 직접 옮겨 적는다. Claude는 **대화창에 글자로** 보여 준다 (문서 도구로 따로 만들지 않는다)
- 형식: 분야별 대괄호 제목 + `- ` 항목. 분야는 그날 한 일에 맞춰 `[분석]` `[기획]` `[설계]` `[개발]` `[환경]` `[일정]` 중에서 쓴다. 세세하고 구체적으로, 실제로 한 일만
- 원장님 요청 번호("원장님 요청 1" 같은 표시)는 적지 않는다. 기능 이름으로 쓴다
- 마지막은 `[일정]` 한 줄: "n단계(이름) 진행률 약 x%". 단계가 끝나는 날에만 "계획 대비 n일 단축"(한 단계 1~2일)을 적는다
- 그 아래 작업 시간: 시작 시각(세션 기록)과 지금 시각(`date`)으로 실제 경과 시간을 적는다. 시간은 범준님이 최종으로 정한다
- 작업량 추정을 물으면 실제 경과 시간을 먼저 말하고, "AI를 쓰는 개발자 기준" 추정은 참고용이라고 밝히고 항목별 근거와 함께 말한다

## 3. 원장님께 보내는 것

- 1단계 완료 = 개발 범위 확인서(`docs/LEET_Elite_개발범위확인서.pdf`, 원문 `docs/scope-summary.md`)를 원장님이 확정하는 것. 개발 계획서는 9/29에 이미 드림
- 확인서를 다시 보내기 전에: 원장님 추가 요청 반영, 화면 캡처 다시 찍기(`LEET_REAL_DATA=0` 서버), 문구가 지금 화면과 맞는지 확인
- 새 기능(범위 추가)은 비용·일정을 범준님이 정한다. 정하기 전에는 확인서에 "별도 협의"로 둔다
- 원장님께 확인할 것은 생기는 대로 `docs/progress.md` 남은 일과 `docs/requests-*.md`에 모아 둔다

## 4. 커밋·푸시

- 푸시를 물을 때 화면이 바뀌는 커밋인지 함께 말한다 (main 푸시 = 시연 주소 배포)
- 푸시한 뒤 Vercel 배포 완료 여부는 Claude가 확인하지 않는다(권한 검사에서 막힘). 범준님이 시연 주소나 Vercel에서 확인한다

## 5. 개발 환경 주의사항

- **플러그인은 사용자 범위로 설치한다** (`claude plugin install <이름> --scope user`). 프로젝트 범위로 깔면 VSCode 확장에서 로드되지 않았다. 설치 기록의 경로(`C:\`)와 VSCode 작업 폴더(`c:\`)의 대소문자 차이로 추정. 지금 사용 중: frontend-design, typescript-lsp, context7, feature-dev
- **Supabase MCP는 개인 액세스 토큰 방식**: `.mcp.json`에는 `Authorization: Bearer ${SUPABASE_ACCESS_TOKEN}` 변수 이름만 둔다. 브라우저 인증은 Claude Code가 주소의 `?project_ref=…`를 잘못 인코딩해서 "Resource must be a valid MCP endpoint"로 실패한다
  - 토큰: Supabase 계정 설정 → Access Tokens, **Project 범위(dev 프로젝트 하나) + Read-only**, 만료 30일. 윈도우 사용자 환경변수 `SUPABASE_ACCESS_TOKEN`에만 저장
  - 토큰은 대화창에 붙이거나 캡처하지 않는다. 노출되면 바로 Revoke하고 새로 만든다
  - 만료가 다가오면(10/5 발급 → 11/4경) 새 토큰을 만들어 환경변수만 바꾼다
- 환경변수·플러그인·`.mcp.json`을 바꾼 뒤에는 **VSCode를 완전히 껐다 켠다** (창 다시 로드로는 안 될 수 있음)
- MCP 인증은 `/mcp`에서 한다. Claude가 대신 할 수 없다
- 상태줄(컨텍스트 사용량)은 터미널 Claude Code에서만 보인다
- 새로 설치한 CLI(gh 등)가 Claude 셸에서 안 보이면 PATH를 다시 읽어야 한다. VSCode를 다시 켜면 해결된다

## 6. 코드에서 걸렸던 점

- `cn()`은 클래스를 이어 붙이기만 한다(충돌 정리 없음). 같은 속성 클래스 두 개(`w-full`과 `w-[84px]` 등)를 겹쳐 주지 말고, 폭이 정해진 칸은 `controlBase`처럼 폭을 뺀 스타일을 쓴다
- 시간 입력은 `<input type="time">` 대신 `TimeSelect`(24시간제 시·분 선택칸)를 쓴다
- `"use client"`는 서버에서 직접 부르는 입구 부품에만 붙인다. 클라이언트 부품 안에서만 쓰는 부품에 붙이면 함수 props 경고가 난다
- 화면 흐름 테스트에서 Tailwind 색은 `oklab(… / 0.5)`처럼 돌아온다. 정확한 rgb 대신 "같은 값인지·다른 값인지"로 비교한다
- 화면 확인용 캡처는 `LEET_REAL_DATA=0`으로 켠 3200번 서버에서 Playwright 스크립트로 찍는다 (스크립트·캡처는 scratchpad에 두고 저장소에 넣지 않는다)
