# 작업 방식 (범준님과 Claude가 반복해서 쓰는 규칙)

CLAUDE.md의 "작업 규칙"·"개인정보·보안"에 있는 내용은 여기에 다시 적지 않는다. 여기는 그 밖에 세션을 거치며 정한 방식이다.

## 1. 하루 진행

- 범준님은 하루 목표를 한 번에 말한다. Claude는 기능 단위로 쪼개서 하나씩 끝낸다: 만들기 → tsc·lint·테스트 → **화면 캡처로 직접 확인** → 로컬 커밋
- 기능 하나가 끝나면 짧게 보고한다: 무엇을 했나 / 어디서 보나(파일·주소) / 확인할 점 + 커밋 해시. 새 개념이 나왔으면 끝에 "오늘의 코드 포인트" 2~3개를 비유로 붙이고 `docs/code-guide.md` "날짜별 배운 것"에 적는다
- "현황"을 물으면 `docs/progress.md`의 단계 표와 `docs/requirements.md`의 요구사항 ID를 기준으로 답한다. "화면(가상 데이터)"과 "실제 동작(DB 연결)"을 나눠 말한다
- 디자인·화면 개선은 바로 고치지 않고 **찾은 문제 목록 → 범준님이 고름 → 고른 것만 적용**. 적용한 것과 보류한 것은 `docs/decisions.md`에 적는다
- 큰 디자인 변경은 앱 코드와 분리된 시안(디자인 캔버스)으로 먼저 보여 준다. frontend-design 스킬은 정해 둔 토큰·규칙 안에서 배치·위계를 다듬을 때만 쓴다
- 디자인 기준은 `docs/design.md`, 눌러 보는 미리보기는 `/design-system`. 새 부품·움직임은 미리보기에 먼저 올리고 범준님 확인 → 화면 적용
- 여러 화면을 한꺼번에 바꾸는 작업은 브랜치(예: `design-system`)에서 하고, 확인받은 뒤 main에 합친다(fast-forward). 화면 하나 끝날 때마다 커밋
- 화면 적용 때는 **바뀐 화면만** 전후 캡처로 비교한다. 바꾸기 전 캡처는 작업 시작 때 한 번 찍어 둔다
- 범준님이 "보여 줘"라고 하면 전후 캡처를 나란히 놓은 비교 페이지(claude.ai 아티팩트, 비공개)를 만든다. 가상 데이터 캡처만 쓴다
- 큰 기능을 바꾸기 전에는 기존 결정(`decisions.md`)과 부딪히는지 먼저 확인하고, 부딪히면 선택지로 물어본다 (예: 10/5 키패드 4자리 고정 ↔ 9/29 "4~6자리")

## 2. 작업일지 (작업 내역)

- 범준님이 작업일지 시트(날짜 · 시작 · 끝 · 총 시간 · 작업내역)에 직접 옮겨 적는다. Claude는 **대화창에 글자로** 보여 준다 (문서 도구로 따로 만들지 않는다)
- 형식: 분야별 대괄호 제목 + `- ` 항목. 분야는 그날 한 일에 맞춰 `[분석]` `[기획]` `[설계]` `[개발]` `[환경]` `[일정]` 중에서 쓴다. 세세하고 구체적으로, 실제로 한 일만
- 원장님 요청 번호("원장님 요청 1" 같은 표시)는 적지 않는다. 기능 이름으로 쓴다
- **작업일지는 원장님께 보여 드리는 것이다.** 개발 환경·내부 설정(플러그인, Supabase 토큰, VSCode, 작업 방식 문서, 커밋 전 검사 등)은 빼고, 원장님이 이해하는 말로 쓴다("낙관적 업데이트" → "누르는 즉시 화면에 반영")
- 작업일지를 만들 때는 그날 커밋 기록(`git log --since`)과 대조해서 빠진 일이 없는지 확인한다
- **(10/6 원장님 요청) `[작동]` 항목을 맨 위에 둔다: "오늘 실제로 작동하게 된 기능"** (시연 주소·실제 DB에서 눌러서 되는 것만. 화면만 만든 것·준비 작업은 넣지 않고, 없는 날은 "없음 (준비 작업: …)"으로 솔직하게)
- 마지막은 `[일정]` 한 줄: "n단계(이름) 진행률 약 x%". 단계가 끝나는 날에만 "계획 대비 n일 단축"(한 단계 1~2일)을 적는다
- 그 아래 작업 시간: 시작 시각(세션 기록)과 지금 시각(`date`)으로 실제 경과 시간을 적는다. 시간은 범준님이 최종으로 정한다
- 작업량 추정을 물으면 실제 경과 시간을 먼저 말하고, "AI를 쓰는 개발자 기준" 추정은 참고용이라고 밝히고 항목별 근거와 함께 말한다

## 3. 원장님께 보내는 것

- 1단계 완료 = 개발 범위 확인서(`docs/LEET_Elite_개발범위확인서.pdf`, 원문 `docs/scope-summary.md`)를 원장님이 확정하는 것. 개발 계획서는 9/29에 이미 드림
- 확인서를 다시 보내기 전에: 원장님 추가 요청 반영, 화면 캡처 다시 찍기(`LEET_REAL_DATA=0` 서버), 문구가 지금 화면과 맞는지 확인
- 새 기능(범위 추가)은 비용·일정을 범준님이 정한다. 정하기 전에는 확인서에 "별도 협의"로 둔다
- 원장님께 확인할 것은 생기는 대로 `docs/progress.md` 남은 일과 `docs/requests-*.md`에 모아 둔다

## 4. 커밋·푸시

- 푸시를 물을 때 화면이 바뀌는 커밋인지 함께 말한다 (main 푸시 = 시연 주소 배포)
- 푸시한 뒤 Vercel 배포 완료 여부는 Claude가 확인하지 않는다(권한 검사에서 막힘). 범준님이 시연 주소나 Vercel에서 확인한다

## 5. 개발 환경 주의사항

- **플러그인은 사용자 범위로 설치한다** (`claude plugin install <이름> --scope user`). 프로젝트 범위로 깔면 VSCode 확장에서 로드되지 않았다. 설치 기록의 경로(`C:\`)와 VSCode 작업 폴더(`c:\`)의 대소문자 차이로 추정. 지금 사용 중: frontend-design, typescript-lsp, context7, feature-dev
- **Supabase MCP는 개인 액세스 토큰 방식**: `.mcp.json`에는 `Authorization: Bearer ${SUPABASE_ACCESS_TOKEN}` 변수 이름만 둔다. 브라우저 인증은 Claude Code가 주소의 `?project_ref=…`를 잘못 인코딩해서 "Resource must be a valid MCP endpoint"로 실패한다
  - 토큰: Supabase 계정 설정 → Access Tokens, **Project 범위(dev 프로젝트 하나) + Read-only**, 만료 30일. 윈도우 사용자 환경변수 `SUPABASE_ACCESS_TOKEN`에만 저장
  - 토큰은 대화창에 붙이거나 캡처하지 않는다. 노출되면 바로 Revoke하고 새로 만든다
  - 만료가 다가오면(10/5 발급 → 11/4경) 새 토큰을 만들어 환경변수만 바꾼다
- 환경변수·플러그인·`.mcp.json`을 바꾼 뒤에는 **VSCode를 완전히 껐다 켠다** (창 다시 로드로는 안 될 수 있음)
- MCP 인증은 `/mcp`에서 한다. Claude가 대신 할 수 없다
- 상태줄(컨텍스트 사용량)은 터미널 Claude Code에서만 보인다
- 새로 설치한 CLI(gh 등)가 Claude 셸에서 안 보이면 PATH를 다시 읽어야 한다. VSCode를 다시 켜면 해결된다

## 6. 코드에서 걸렸던 점

- `cn()`은 클래스를 이어 붙이기만 한다(충돌 정리 없음). 같은 속성 클래스 두 개(`w-full`과 `w-[84px]` 등)를 겹쳐 주지 말고, 폭이 정해진 칸은 `controlBase`처럼 폭을 뺀 스타일을 쓴다
- 시간 입력은 `<input type="time">` 대신 `TimeSelect`(24시간제 시·분 선택칸)를 쓴다
- `"use client"`는 서버에서 직접 부르는 입구 부품에만 붙인다. 클라이언트 부품 안에서만 쓰는 부품에 붙이면 함수 props 경고가 난다
- 화면 흐름 테스트에서 Tailwind 색은 `oklab(… / 0.5)`처럼 돌아온다. 정확한 rgb 대신 "같은 값인지·다른 값인지"로 비교한다
- 화면 확인용 캡처는 `LEET_REAL_DATA=0 LEET_E2E=1`로 켠 3200번 서버에서 `node scripts/capture-screens.mjs <저장 폴더> [이름 일부]`로 찍는다. 스크립트는 저장소에 있고(10/6), **캡처 파일은 저장소 밖(scratchpad 등)에** 둔다. 원장님께 보낼 캡처만 골라 `docs/preview/`에
- (10/5) Tailwind v4의 `translate-x-*`는 `transform`이 아니라 `translate` 속성이다. 움직이려면 `transition-[translate]`로 적는다
- (10/5) 저장 중 화면 반영은 `src/lib/use-optimistic-save.ts` 하나로. React 19는 동시에 진행 중인 비동기 저장을 함께 확정하므로, 단위 테스트에서 끝내지 않은 저장을 남기면 다음 테스트가 멈춘다
- (10/5) 창(Sheet)의 닫힘 움직임: 창 밖 버튼은 `closeRef`, 창 안 버튼은 `useSheetClose()`. 부모가 바로 없애면 닫히는 모습이 안 보인다
- (10/5) 화면 흐름 테스트는 `e2e/ready.ts`의 `gotoReady`로 연다: `<html data-hydrated>`(준비 끝)와 스켈레톤(`aria-busy`) 사라짐을 기다린다. 안 그러면 가끔 누른 것이 되돌아가거나 개수가 0으로 센다
- (10/5) Playwright `page.clock`은 타이머·Date만 멈춘다. CSS 움직임은 실제 시간으로 흐르므로 캡처할 때는 실제로 기다린다
- (10/5) `/kiosk`는 미리 만들어 두는 정적 페이지라 서버에서 "오늘"을 계산하면 빌드한 날로 굳는다. 오늘 요일·시각은 브라우저에서 계산한다
- (10/5) 단위 테스트는 실제 명단 파일이 있어도 항상 가상 데이터로 돈다 (`vitest.config.ts`의 `LEET_REAL_DATA: "0"`)
- (10/6) **로그인 출입 통제(`src/proxy.ts`)가 생겨서** 로그인 없이는 화면이 `/login`으로 간다. 로컬에서는 시험 계정(`admin`·`teacher`…, `docs/handover/database.md` 3-5번)으로 로그인해서 본다. 화면 흐름 테스트는 개발 서버에 `LEET_E2E=1`을 주고 요청 머리글 `x-leet-e2e-no-auth: 1`이 달린 요청만 통과시킨다(`playwright.config.ts`, 배포판에서는 무시). 캡처 스크립트도 같은 머리글을 단다
- (10/6) Next 16은 **한 폴더에서 개발 서버를 하나만** 켤 수 있다("Another next dev server is already running"). 테스트 전에 켜 둔 서버(3000·3200 등)를 끈다
- (10/6) `cn()` 겹침 함정이 또 나왔다: 시트의 `md:w-full` + 넘겨받은 `md:w-[520px]`(태블릿에서 화면 전체), 버튼 모양의 `inline-flex` + `hidden`(숨겨지지 않음). **보이기·숨기기·폭은 바깥 칸에서** 정한다
- (10/6) Git Bash에서 `node 스크립트 "/admin"`처럼 /로 시작하는 인자는 윈도우 경로로 바뀐다 → `MSYS_NO_PATHCONV=1`
- (10/6) 이 저장소는 Prettier를 쓰지 않는다. `npx prettier --write`를 돌리면 파일 전체가 바뀐다(되돌림)
- (10/6) 이 환경의 sandbox는 글꼴 같은 바이너리를 `public/`으로 복사하는 것을 막는다(조용히 exit 127). 패키지 파일을 CSS에서 상대 경로로 가리키면 빌드가 알아서 내보낸다(`src/app/pretendard.css`)
- (10/6) 화면 흐름 테스트에서 시트 손잡이를 끌 때는 올라오는 움직임(0.25초)이 끝난 뒤 위치를 잰다
- (10/6) 성능(LCP·CLS)은 개발 서버가 아니라 빌드판(`npm run build` → `next start`)에서, CPU 4배 느리게·캐시 없이 잰다. 개발 서버와 함께 켤 수 없으니 하나씩
- (10/6) `Button`은 서버 화면에서도 쓰이므로 안에서 함수를 새로 만들어 달면 안 된다(서버 화면이 통째로 에러). 받은 `onClick`을 그대로 넘기거나 떼는 것만

## 7. 세션을 비우기(클리어) 전에

범준님이 "클리어할 거야"라고 하면 **먼저 저장하고 나서** 끝낸다.

1. `docs/progress.md` 세션 기록 맨 위에 **"다음 세션 시작점"** 블록을 새로 쓴다: 작업 시간(시작~지금, `date`), 오늘 한 일 순서, 푸시 상태(푸시한 마지막 커밋 / 안 한 커밋), 다음 할 일(순서대로), 원장님께 확인할 것, 범준님이 결정할 것, 기억할 것. 이전 시작점 블록은 "(지난)"으로 표시
2. 세션 중에 새로 정한 작업 방식·규칙은 이 문서(`workflow.md`)에, 코드에서 걸렸던 점은 6번에 더한다
3. 결정사항은 `docs/decisions.md`, 공부용 설명은 `docs/code-guide.md` "날짜별 배운 것"에 빠진 것이 없는지 확인
4. 위 문서들을 커밋한다 (푸시는 따로 묻는다)
5. 범준님께 "저장한 곳 + 다음 세션에서 이어 갈 첫 할 일"을 짧게 알린다
